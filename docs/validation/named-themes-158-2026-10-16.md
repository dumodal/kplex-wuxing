## Content and decisions

The version1 library stores stable theme IDs, display names, selected ID, migration completion and a dismissible migration-message flag in one JSON container. Each appearance has `base` and `semantic` sections. Base captures the thirteen standard records, canvas source and native/legacy baseline. Semantic captures complete custom style records, tag order, a private named palette/slot map, Compass preferences and only the lens color projection by stable lens ID. Ontology, style-property selection, labels, typography profiles, layout/navigation, image consent and lens expressions/enabled/order/filtering remain global.

Factory theme identity is `default`. Existing appearances produce independent `user` and `native-base` snapshots plus factory. Successfully imported first-run ExcaliBrain appearance uses that same migration path; only a genuinely fresh/no-import installation starts with factory alone. The host must first use existing settings migration to retain historical effective defaults, then capture before adoption. Unsupported/future data must remain raw/read-only and cannot certify a fallback as a backup.

Source resets clear known color fields only. Semantic reset retains rule keys, non-color styles, tag ordering, palette entries, Compass enabled/intensity and lens behavior. Base-only uses the existing native-adoption operation. Stored colors remain identities/inheritance; no computed RGB is captured. A preserved base reference to a semantic slot can change resolution after a semantic reset.

Theme application touches only existing stable-ID lenses, first removing their prior theme color projection. It cannot recreate deleted lenses or carry colors into a lens without a newly selected override. Copies do not share mutable appearance state. Rendering must read only active effective appearance; inactive metadata operations must not request scene or graph work.
