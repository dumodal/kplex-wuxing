## Problem and correction

Three real prose-only Vault saves in the guarded Windows Small vault reproduced unchanged
final numbers but repeated transient zero/unknown/lower-bound badges. The bounded observer
reached its 96-mutation cap. The root folder's child count also temporarily fell from its
native total to the smaller induced scope. Tag/folder lateral gates displayed unknown counts.

An ordinary edit temporarily invalidates global source completion. A previously compiled
Eager source could then enter the local bootstrap path; after handover discarded the local
admission token, forced compilation bypassed the existing source-fingerprint no-op check.
Facade replacement also discarded native folder count proof, and presentation coverage changes
alone changed badge text despite identical displayed values.

The correction stays in the existing GraphIndex/GraphBuilder and node-presentation owners:

- A runtime-only scalar on the existing hot body entry records the policy of a real canonical
  source commit. Current native identity, a canonical fingerprint and this policy marker let
  an already compiled Eager owner use the ordinary foreground patch path. Actual input parsing,
  source acquisition, fingerprint comparison and final revision checks remain mandatory. Cold,
  evicted and changed-policy inputs cannot borrow the marker. Node-only repairs do not stamp it.
- The fingerprint no-op receipt is distinguished from a node-only repair. An exactly attributed
  source revision can retain its predecessor read because the old revision closes write authority.
  Identity-only resolver/cache notifications still retire affected scopes, including released history.
  Such a save retains
  coherent requested read presentation while its new proof prepares. Retention never restamps
  source, maintenance, policy or relationship-write authority. Changed incidence retires it at
  the existing atomic commit; deletion/rename and policy guards remain independent. Fresh host
  preview priority is preserved when canonical repair is blocked.
- Replacement requested folder facades inherit only an existing topology- and visibility-fenced
  native count proof. Semantic incidence and write authority are not copied.
- Each mounted node retains four committed badge labels when values are unchanged and coverage
  alone becomes temporarily weaker. The existing cached-count tooltip identifies retained text.
  Changed values/numerators, unavailable inputs, complete proof, navigation and native file
  replacement update/reset the display immediately. No index proof is changed by this UI state.
- Tag/folder friend/challenger gates display exact `0` even while hierarchy counts are partial.
  Ordinary unknown counts keep their existing notation, and the count visibility preference stays.

No schema, persisted setting, new timer, global proof cache, debounce, watchdog, lease or count
maintenance algorithm is changed. Freshness validation still runs; this is not a zero-CPU save.
